# Plan 02 — M3.3: P2P fast path (iroh endpoint, gossip, lease handoff)

Read `docs/plans/CONVENTIONS.md` first. Prerequisites: plans 00–01
committed. Spec: `docs/DESIGN.md` §8 "Security" (transport, authz,
node keys), §4 "Leases" (P2P-accelerated transfer), §12 "push
invalidation". Roadmap exit criterion: **lease transfer ~1 RTT when
peers are connected**; push invalidation replaces waiting out
poll-interval+TTL.

S3 remains the source of truth and the commit point — P2P is ONLY an
accelerator. Every feature in this plan must degrade to the current
S3-polling behavior when peers are unreachable. That property is what
the fault-injection scenarios check.

## Step 1 — Node identity and registry

- `constellation host init`: generate an Ed25519 node key at
  `~/.config/constellation/node.key` (0600) if absent. Mount
  auto-generates one when missing (log it), keyed per host — NOT per
  state dir.
- Extend the node registry object (`store-s3::nodes`, currently
  `{node_id, hostname, created_unix}`) with `pubkey` (hex) and
  `iroh_addr` (the serialized iroh NodeAddr/ticket, refreshed at mount
  and periodically — CAS-swap the node's own object; it is the only
  writer, so a plain PUT overwrite is acceptable, document why).
- Accept-time allowlist: a peer connection is accepted only if its
  pubkey appears in `registry/` (refresh the cached registry on miss
  before rejecting). Self-enrollment requires bucket write, so IAM
  remains the trust root (DESIGN.md).

## Step 2 — iroh endpoint in the `net` crate

The `crates/net` crate is currently an empty skeleton. Add `iroh` and
`iroh-gossip` (latest compatible releases; pin exact versions in the
workspace `Cargo.toml`). Build:

- `Endpoint::bind(node_key)` — one QUIC endpoint per daemon,
  discovery unpublished (peers learn addresses from the registry
  only).
- A tiny length-prefixed CBOR (or serde_json to match the codebase —
  choose one, document it) message layer with one ALPN for direct
  requests and iroh-gossip for the broadcast topic. Topic ID derives
  from a secret stored in `meta.json` at `fs create`
  (`gossip_secret`, random 32 bytes; add the field with serde default
  so existing filesystems keep mounting — derive the topic from the
  fs UUID when the secret is absent and note the weaker property in
  the module doc).
- Message types (all signed by the sender's node key; verify before
  acting):
  - `SegmentPublished { part, seq, epoch }` — gossip, fired after
    every successful segment PUT.
  - `LeaseRequest { part, requester }` / `LeaseHandoff { part, epoch,
    released: bool }` — direct messages between requester and holder.
  - `Ping/Pong` — liveness for status UX only (never a safety input).

## Step 3 — Push invalidation (gossip-driven tailing)

Today cross-node visibility = sync interval (500 ms default) + FUSE
attr TTL (1 s). Wire `SegmentPublished` into the syncer: on receipt,
nudge an immediate sync round (the channel already exists —
`SyncRequest`). After applying foreign records, invalidate affected
kernel entries: collect touched inos/parents from the applied records
and call `fuser::Notifier::inval_entry`/`inval_inode` (fuser 0.15
exposes the notifier from `Session`; if the currently-used mount API
makes the notifier inaccessible, switch the mount call to the
Session-based variant — keep `mount2` semantics otherwise). With push
invalidation in place, raise the FUSE attr/entry TTLs from 1 s to
`CONSTELLATION_FUSE_TTL_S` default 30 for peers-connected operation —
BUT only when gossip is live (fall back to 1 s TTLs when no peers or
gossip is down; make the TTL choice dynamic per-reply based on
current gossip health).

## Step 4 — Lease handoff in ~1 RTT

Current handover latency = idle-release window (2 s) or TTL expiry.
Add the fast path: when a node wants a lease that another live node
holds, it sends `LeaseRequest` directly. The holder, on receipt:
finishes in-flight mutations, flushes its journal for that partition
(ship to S3 — the commit point stays S3), releases the lease via CAS
(`released: true`), and replies `LeaseHandoff`. The requester then
CAS-claims (tail-to-head first, as always — it just got the
`SegmentPublished` for the final flush, so the tail is one round).
Total: ~1 RTT of P2P plus the S3 CAS pair, exactly the DESIGN.md
shape ("holder flushes + hands off in one RTT with the S3 CAS as the
commit point").

- The FUSE-side lease wait (currently poll-with-deadline against S3)
  fires a `LeaseRequest` first and keeps the S3 poll as fallback.
- Keep the idle-release behavior as the no-P2P fallback, but raise
  the default idle window (e.g. to 10 s) once handoff works — the
  fast path makes aggressive idle-release unnecessary, and fewer
  releases = fewer reacquire CAS round-trips for a single active
  writer. Verify `two-clients-shared` and `git-workflow` get FASTER,
  not slower.

## Step 5 — Wiring, status, config

- The daemon (main.rs mount path) starts the endpoint, joins gossip,
  publishes its registry record, and hands the net handles to the
  syncer and the lease keeper. All P2P failures are non-fatal: log +
  degrade to polling.
- `CONSTELLATION_P2P=off` env kill-switch (scenarios use it to prove
  degradation).
- Control API: `StatusReport.p2p: { enabled, node_addr, peers:
  [{node_id, connected, rtt_ms}] }` (serde defaults). Show in
  `status`.

## Step 6 — Tests

Unit: message sign/verify round-trip; allowlist rejection of an
unknown pubkey; handoff state machine against InMemory stores with a
loopback duplex stream standing in for the QUIC pair (keep the
transport behind a small trait so the state machine is testable
without sockets).

Harness scenarios:
- `p2p-handover`: two nodes, P2P on; measure that a blocked writer on
  B acquires the lease from an ACTIVE holder A in well under the idle
  window (assert < 1 s end-to-end via the control API timestamps);
  conflicts stay 0; model-verified trees.
- `p2p-invalidation`: A writes a file, B must observe the new content
  strictly faster than the no-P2P visibility bound (sync interval +
  TTL); assert via polling `eventually()` with a tight deadline
  (e.g. 500 ms). Then set `CONSTELLATION_P2P=off` on both and verify
  the old bound still holds (degradation works).
- `p2p-partition-tolerance`: cut the P2P path between the nodes
  (toxiproxy only proxies S3; for P2P use the kill-switch env on one
  node instead, or SIGSTOP the peer — document the choice), and
  verify everything from `two-clients-shared` still passes on the S3
  slow path.

## Out of scope

Cooperative chunk serving over P2P (phase 5 — but the endpoint/message
layer you build is its foundation; keep the ALPN/message enum
extensible), offline designation acks (phase 4), relay servers beyond
iroh's defaults.
